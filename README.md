## 4. Автомат тестийн хэрэгжүүлэлт

SauceDemo веб систем дээр дараах гурван функционал тестийг боловсруулсан.

### TC-01: Амжилттай нэвтрэх

Зөв хэрэглэгчийн нэр болон нууц үг ашиглан системд нэвтэрнэ. Inventory хуудас нээгдсэн болон Products хэсэг харагдаж байгааг шалгана. Дараа нь Logout үйлдэл хийж, нэвтрэх хуудас руу буцсаныг баталгаажуулна.

**Хүлээгдэж буй үр дүн:** Хэрэглэгч системд амжилттай нэвтэрч, гарах боломжтой байна.

### TC-02: Амжилтгүй нэвтрэх

Зөв хэрэглэгчийн нэр, буруу нууц үг ашиглан нэвтрэх оролдлого хийнэ. Алдааны мэдээлэл гарсан болон хэрэглэгч нэвтрэх хуудсан дээр хэвээр байгааг шалгана.

**Хүлээгдэж буй үр дүн:** Систем нэвтрэх эрх олгохгүй бөгөөд алдааны мэдээлэл харуулна.

### TC-03: Бараа сагслах

Системд амжилттай нэвтэрч, Sauce Labs Backpack барааг сонгон сагсанд нэмнэ. Сагсны барааны тоо нэг болсон эсэхийг шалгаж, сагсны хуудсанд сонгосон бараа байгаа эсэхийг баталгаажуулна.

**Хүлээгдэж буй үр дүн:** Сонгосон бараа сагсанд амжилттай нэмэгдэнэ.

## 5. Locator болон Assertion

Веб хуудасны элементүүдийг тодорхойлохдоо орчин үеийн locator ашигласан.

```typescript
page.getByPlaceholder('Username');
page.getByRole('button', { name: 'Login' });
page.getByText('Products', { exact: true });
```

Тестийн үр дүнг баталгаажуулахдаа дараах assertion-уудыг ашигласан.

```typescript
await expect(page).toHaveURL(/inventory\.html$/);

await expect(
  page.getByText('Products', { exact: true })
).toBeVisible();

await expect(
  page.locator('.shopping_cart_badge')
).toHaveText('1');
```

XPath ашиглаагүй бөгөөд элементүүдийг нэр, зориулалт болон харагдах мэдээллээр тодорхойлсон.

Тест бүр тусдаа browser context ашигладаг тул өмнөх тестийн session болон cookie дараагийн тестэд нөлөөлөхгүй.

## 6. Codegen туршилт

Playwright Codegen ашиглан нэвтрэх болон бараа сагслах үйлдлүүдийг автоматаар код болгон үүсгэж туршсан.

```bash
npx playwright codegen https://www.saucedemo.com/
```

| Үзүүлэлт | Codegen | Үндсэн тест |
|---|---|---|
| Locator | data-test | getByRole, getByText, getByPlaceholder |
| Assertion | Туршилтын бичлэгт нэмээгүй | expect ашигласан |
| Үйлдэл | Автоматаар бүртгэсэн | Шаардлагад тохируулсан |
| Тестийн бүтэц | Үйлдлийн дараалал | 3 тусдаа тест |

Codegen нь тестийн анхны кодыг хурдан үүсгэхэд тохиромжтой байсан. Гэхдээ шаардлагагүй товшилт болон гарын товчлуурын үйлдлүүд бүртгэгдэж байсан тул үүссэн кодыг шалгаж, сайжруулах шаардлагатай гэж үзсэн.

## 7. Trace Viewer болон алдааны шинжилгээ

Trace идэвхжүүлж тест ажиллуулсан.

```bash
npx playwright test --trace on --reporter=html
```

Амжилттай нэвтрэх тестийн URL assertion-ийг зориудаар буруу болгож туршсан.

```typescript
await expect(page).toHaveURL(/wrong-page.html/);
```

Тест амжилтгүй болсон бөгөөд Trace Viewer ашиглан хүлээгдэж буй URL болон бодит URL хоорондоо зөрж байгааг тодорхойлсон.

Мөн олон хөтөч дээр тест ажиллуулах үед Firefox-ийн browser context болон WebKit-ийн Logout үйлдэлтэй холбоотой timeout алдаа гарсан.

Алдааг шийдвэрлэхийн тулд:

- Worker-ийн тоог 1 болгосон.
- Locator болон тестийн бүтцийг шинэчилсэн.
- Logout үйлдлийг амжилттай нэвтрэх тестэд төвлөрүүлсэн.
- Тестүүдийг давтан ажиллуулж шалгасан.

Шинэчилсэн хувилбар дээр гурван хөтөчийн бүх тест амжилттай ажилласан.

## 9. Playwright болон Selenium-ийн харьцуулалт

Playwright болон Selenium нь веб системийн UI автомат тест хийх нээлттэй эхийн хэрэгслүүд юм. Playwright нь auto-wait механизмтай учраас элемент бэлэн болохыг автоматаар хүлээдэг. Selenium-д зарим нөхцөлд explicit wait бичих шаардлагатай байдаг. Playwright нь шаардлагатай хөтчүүдийг нэг командаар суулгах боломжтой. Selenium нь WebDriver стандартад суурилдаг бөгөөд олон программчлалын хэлтэй ажиллах өргөн экосистемтэй. Playwright-ийн Codegen нь хэрэглэгчийн үйлдлийг автоматаар тестийн код болгон үүсгэдэг. Trace Viewer ашиглан тестийн алдаа гарсан алхам болон веб хуудасны төлөвийг шинжлэх боломжтой байсан. Мөн Playwright нь тест бүрийг тусдаа browser context-д ажиллуулдаг нь тестийн тусгаарлалтыг хэрэгжүүлэхэд хялбар болгосон. Энэ лабораторийн хувьд Playwright нь тест бичих, ажиллуулах, алдаа шинжлэх болон тайлагнахад тохиромжтой байсан.

Энэхүү харьцуулалтыг хэрэгслүүдийн боломж болон Playwright дээр хийсэн туршилтад үндэслэсэн бөгөөд Selenium дээр гүйцэтгэлийн хугацаа хэмжээгүй.

## 10. AI ашигласан байдал

Лабораторийн ажлын явцад ChatGPT-ийг тестийн код боловсруулах, тохиргоо хийх, алдаа шинжлэх болон баримтжуулалтад туслах хэрэгсэл болгон ашигласан. AI-ийн санал болгосон кодод locator болон assertion ашиглах жишээнүүд байсан. Гэвч Logout элементийг анх буруу role-оор тодорхойлсноос timeout алдаа гарсан. WebKit дээр гарсан алдааг шийдвэрлэх анхны зөвлөмжүүд мөн бүрэн үр дүнтэй байгаагүй. Иймээс тестүүдийг давтан ажиллуулж, алдааны мэдээлэлд үндэслэн код болон тохиргоог шинэчилсэн. Эцсийн хувилбарыг гурван хөтөч дээр ажиллуулж, 9/9 PASS үр дүнгээр баталгаажуулсан. AI-ийн санал болгосон кодыг бодит туршилтаар шалгаж ашиглах шаардлагатай гэж дүгнэсэн.
